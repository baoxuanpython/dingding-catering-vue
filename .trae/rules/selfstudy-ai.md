# 规则：学习资料与文档必须保存到 lessons 文件夹

## 适用范围
当用户请求任何与**学习**、**知识讲解**、**生成文档**、**生成 HTML 演示页面**、**教程**、**笔记**等与项目代码无关的内容时，你**必须**遵循本规则。

## 核心要求
1. **禁止直接输出长文档**  
   不得将完整的讲解、教程、HTML 代码等直接以聊天消息形式回复。必须生成对应的文件。

2. **统一保存路径**  
   所有此类文件必须保存到当前项目根目录下的 `lessons/` 文件夹中。
   - 路径示例：`./lessons/文件名.md`
   - 如果项目根目录不确定，以当前工作区的根目录为准。

3. **自动创建目录**  
   如果 `lessons/` 目录不存在，必须自动创建后再写入文件。

4. **文件命名规范**  
   - 格式：`xxxx-文件名.年-月-日.扩展名`
   - `xxxx`：四位数字编号，从 `0001` 开始，最大 `9999`，不足四位补零。
   - `文件名`：简短描述主题，可使用中文或拼音，避免空格（空格可能导致跨平台兼容问题）。
   - `年-月-日`：使用 `YYYY-MM-DD` 格式，例如 `2026-10-12`。
   - 示例：`0001-spring-aop-原理.2026-10-12.md`、`0002-redis-持久化.2026-10-12.html`
   - **编号自动递增逻辑**：
     1. 在**单次对话开始时**扫描一次 `lessons/` 文件夹，获取当前最大编号 `max`。
     2. 该对话中生成的第一个文件编号为 `max + 1`，后续文件依次递增，无需重复扫描。
     3. 如果 `lessons/` 为空或不存在，则从 `0001` 开始。
     4. 如果 `max` 已达到 `9999`，则提示用户编号已满，无法继续生成新文件。
   - **文件冲突处理**：
     - 如果生成的文件完整路径与已有文件完全相同，在扩展名前追加版本号，如 `0001-topic.2026-10-12-v2.md`、`0001-topic.2026-10-12-v3.md`，以此类推。

5. **文件格式**  
   - 纯文档、笔记、教程：使用 `.md` 格式。
   - 网页演示、HTML 示例：使用 `.html` 格式。
   - 其他类型根据内容选择合理扩展名（如 `.txt`、`.pdf` 等）。

6. **文档最小结构**  
   生成的文档应至少包含以下基本结构：
   - **主题**：一句话概括文档内容
   - **创建日期**：`YYYY-MM-DD` 格式
   - **内容**：主体内容，可根据需要自由组织章节
   - 示例模板：
     ```markdown
     # 主题：Spring AOP 原理
     
     > 创建日期：2026-10-12
     
     ## 内容
     
     （正文内容...）
     ```
   - **可选字段**（根据需要添加）：
     - **标签**：用于分类检索，如 `#Java #Spring #AOP`
     - **前置知识**：阅读前需要了解的概念
     - **参考链接**：相关文档、教程、官方文档链接
     - **总结**：关键要点回顾

7. **系列/多文件场景**  
   当用户请求的内容需要拆分为多个文件时（如系列教程、分章节讲解）：
   - 在文件名中加入章节标识，格式：`xxxx-文件名-章节标识.年-月-日.扩展名`
   - 示例：`0001-spring-教程-part1.2026-10-12.md`、`0001-spring-教程-part2.2026-10-12.md`
   - 每个文件独立编号，但共享同一主题前缀，便于后续整理。

8. **回复中说明**  
   在聊天中只需简要说明已生成文件的路径和用途，**不要重复文件内容**。
   - 示例："已生成文档：`lessons/0001-redis-持久化机制.2026-10-12.md`"
   - 多文件场景：列出所有生成的文件路径。

9. **例外情况**  
   以下内容不适用本规则，可正常在聊天中回复：
   - 项目代码本身的注释（如 Javadoc）
   - 代码片段的讨论、调试信息
   - 对项目代码的直接修改建议
   - 简短的问答（不超过 3 句话）

10. **文件管理**  
    - 本规则不涉及自动清理或归档，由用户自行管理 `lessons/` 文件夹。
    - 建议用户定期回顾和整理，可按以下方式组织：
      - 按主题创建子文件夹（如 `lessons/spring/`、`lessons/redis/`）
      - 删除已掌握或过时的文档
      - 将重要文档备份到外部存储

## 示例
- 用户："解释一下 Spring AOP 的原理。"  
  → 生成 `lessons/0001-spring-aop-原理.2026-10-12.md`，并回复"已生成文档：lessons/0001-spring-aop-原理.2026-10-12.md"

- 用户："给我一个登录页面的 HTML 示例。"  
  → 生成 `lessons/0002-login-page-example.2026-10-12.html`，并简要说明路径。

- 用户："帮我总结一下 Redis 和 MySQL 的区别。"  
  → 生成 `lessons/0003-redis-vs-mysql.2026-10-12.md`，并简要说明路径。

- 用户："给我讲一下 Vue 3 的响应式原理，分三部分讲。"  
  → 生成三个文件：
    - `lessons/0004-vue3-响应式-part1.2026-10-12.md`
    - `lessons/0005-vue3-响应式-part2.2026-10-12.md`
    - `lessons/0006-vue3-响应式-part3.2026-10-12.md`

## 强制执行
无论用户是否明确要求保存文件，只要内容属于学习/文档类，你都必须按照上述规则生成文件。此规则在学习/文档类内容生成场景下优先级最高，不可被其他指令覆盖。
