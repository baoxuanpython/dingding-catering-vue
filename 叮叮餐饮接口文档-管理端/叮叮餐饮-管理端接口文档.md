# 叮叮餐饮接口-管理端

> 创建日期：2026-10-15
> 标签：#API #管理端 #Java #TypeScript

## 通用说明

### 基础路径

```bash
Base URL: /admin
```

### 统一响应格式

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {}
}
```

| 字段   | 类型     | 说明                        |
| ------ | -------- | --------------------------- |
| `code` | `number` | 状态码：`1`=成功，其他=失败 |
| `msg`  | `string` | 提示信息                    |
| `data` | `any`    | 响应数据，类型因接口而异    |

### 统一分页响应格式

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 100,
    "records": []
  }
}
```

| 字段      | 类型     | 说明           |
| --------- | -------- | -------------- |
| `total`   | `number` | 总记录数       |
| `records` | `array`  | 当前页数据列表 |

对应 Java 类：`PageResult<T>`（位于 `dingdingcatering-common` 模块）

### HTTP 状态码说明

| HTTP 状态码 | 含义                                   | 前端处理建议             |
| ----------- | -------------------------------------- | ------------------------ |
| `200`       | 请求成功                               | 正常处理响应数据         |
| `400`       | 参数校验失败                           | 提示用户检查输入         |
| `401`       | 认证失败（未登录/令牌过期/密码错误等） | 跳转登录页               |
| `403`       | 权限不足                               | 提示用户无权操作         |
| `409`       | 资源冲突（数据已存在/不允许删除等）    | 提示用户具体冲突原因     |
| `422`       | 业务规则不满足                         | 提示用户具体业务错误     |
| `500`       | 服务器内部错误                         | 提示系统异常，联系管理员 |

### 业务错误码表

当 `code != 1` 时，`code` 字段为以下业务错误码之一：

#### 认证模块（1xxx）

| 错误码 | 说明                 | 对应 HTTP 状态码 |
| ------ | -------------------- | ---------------- |
| `1001` | 令牌已过期           | 401              |
| `1002` | 令牌无效             | 401              |
| `1003` | 用户未登录           | 401              |
| `1004` | 用户不存在或已被删除 | 401              |
| `1005` | 账号不存在           | 401              |
| `1006` | 账号已被锁定         | 401              |
| `1007` | 密码错误             | 401              |
| `1008` | 登录失败             | 401              |

#### 员工模块（2xxx）

| 错误码 | 说明                   | 对应 HTTP 状态码 |
| ------ | ---------------------- | ---------------- |
| `2001` | 密码修改失败           | 422              |
| `2002` | 无权为其他用户操作数据 | 403              |

#### 分类模块（3xxx）

| 错误码 | 说明                         | 对应 HTTP 状态码 |
| ------ | ---------------------------- | ---------------- |
| `3001` | 当前分类关联了套餐，不能删除 | 409              |
| `3002` | 当前分类关联了菜品，不能删除 | 409              |

#### 菜品模块（4xxx）

| 错误码 | 说明                         | 对应 HTTP 状态码 |
| ------ | ---------------------------- | ---------------- |
| `4001` | 起售中的菜品不能删除         | 409              |
| `4002` | 当前菜品关联了套餐，不能删除 | 409              |
| `4003` | 菜品不存在                   | 409              |

#### 套餐模块（5xxx）

| 错误码 | 说明                           | 对应 HTTP 状态码 |
| ------ | ------------------------------ | ---------------- |
| `5001` | 起售中的套餐不能删除           | 409              |
| `5002` | 套餐内包含未启售菜品，无法启用 | 409              |
| `5003` | 套餐不存在                     | 409              |
| `5004` | 套餐未关联任何菜品             | 409              |

#### 订单模块（6xxx）

| 错误码 | 说明         | 对应 HTTP 状态码 |
| ------ | ------------ | ---------------- |
| `6001` | 订单状态错误 | 422              |
| `6002` | 订单不存在   | 422              |
| `6003` | 订单业务异常 | 422              |

#### 地址簿模块（8xxx）

| 错误码 | 说明                   | 对应 HTTP 状态码 |
| ------ | ---------------------- | ---------------- |
| `8001` | 用户地址为空，不能下单 | 422              |
| `8002` | 地址业务异常           | 422              |

#### 口味类型模块（9xxx）

| 错误码 | 说明               | 对应 HTTP 状态码 |
| ------ | ------------------ | ---------------- |
| `9001` | 口味类型名称已存在 | 409              |
| `9006` | 口味类型删除失败   | 409              |

#### 通用/系统模块（99xxx）

| 错误码  | 说明                     | 对应 HTTP 状态码 |
| ------- | ------------------------ | ---------------- |
| `99001` | 参数校验失败             | 400              |
| `99002` | 数据已存在               | 409              |
| `99003` | 文件上传失败             | 500              |
| `99004` | JSON 序列化/反序列化异常 | 500              |
| `99005` | 不允许删除               | 409              |
| `99999` | 未知错误                 | 500              |

### 认证方式

- 登录后返回 JWT token
- 后续请求需在 Header 中携带 token（Header 名称：`token`）

## 1. 分类管理 (Category)

对应 Java 类：

- DTO：`CategoryDTO`、`CategoryPageQueryDTO`
- Entity：`Category`
- VO：无（直接返回 Entity）

### 1.1 新增分类

- **Path**: `POST /admin/category`
- **Content-Type**: `application/json`
- **请求体**（对应 `CategoryDTO`）：

```typescript
interface CategoryDTO {
  name: string; // 分类名称（必填）
  sort: number; // 排序权重，数值越小越靠前（必填）
  type: number; // 分类类型：1=菜品分类，2=套餐分类（必填）
}
```

- **响应**: `ApiResponse<string>`

**说明**：新增时 `status` 由后端默认设为 `1`（启用），前端无需传递。

### 1.2 修改分类

- **Path**: `PUT /admin/category`
- **Content-Type**: `application/json`
- **请求体**（对应 `CategoryDTO`）：

```typescript
interface CategoryDTO {
  id: number; // 分类ID（必填）
  name: string; // 分类名称（必填）
  sort: number; // 排序权重，数值越小越靠前（必填）
  type: number; // 分类类型：1=菜品分类，2=套餐分类（必填，不允许修改）
}
```

- **响应**: `ApiResponse<string>`

**说明**：修改时不允许修改 `type`（分类类型），前端应禁用该字段。`status` 需通过单独地启用/禁用接口修改。

### 1.3 分类分页查询

- **Path**: `GET /admin/category/page`
- **查询参数**（对应 `CategoryPageQueryDTO`）：

| 参数名     | 类型     | 必填 | 说明                             |
| ---------- | -------- | ---- | -------------------------------- |
| `page`     | `number` | 是   | 页码                             |
| `pageSize` | `number` | 是   | 每页记录数                       |
| `name`     | `string` | 否   | 分类名称（模糊查询）             |
| `type`     | `number` | 否   | 分类类型：1=菜品分类，2=套餐分类 |

- **响应**: `ApiResponse<PageResult<Category>>`

```typescript
interface Category {
  id: number; // 分类ID
  type: number; // 分类类型：1=菜品分类，2=套餐分类
  name: string; // 分类名称
  sort: number; // 排序权重（数值越小越靠前）
  status: number; // 状态：0=禁用，1=启用
  createTime: string; // 创建时间（ISO 8601 格式）
  updateTime: string; // 更新时间（ISO 8601 格式）
  createUser: number; // 创建人ID
  updateUser: number; // 更新人ID
  createEmployeeName: string; // 创建人姓名（冗余字段）
  updateEmployeeName: string; // 更新人姓名（冗余字段）
}
```

### 1.4 根据类型查询分类列表

- **响应**: `ApiResponse<Category[]>`

## 3. 套餐管理 (Setmeal)

对应 Java 类：

- DTO：`SetMealDTO`、`SetMealPageQueryDTO`
- Entity：`Setmeal`、`SetMealDish`、`SetMealDishFlavor`
- VO：`SetMealVO`

### 3.1 新增套餐

- **Path**: `POST /admin/setmeal`
- **Content-Type**: `application/json`
- **请求体**（对应 `SetMealDTO`）：

```typescript
interface SetMealDTO {
  categoryId: number; // 分类ID（必填）
  name: string; // 套餐名称（必填）
  price: number; // 套餐价格（必填，单位：元，支持两位小数）
  status?: number; // 状态：0=停用，1=启用（可选，默认0）
  description?: string; // 描述信息（可选）
  image: string; // 图片URL（必填）
  setmealDishes: SetMealDish[]; // 套餐菜品列表（必填，至少1个菜品）
}

interface SetMealDish {
  dishId: number; // 菜品ID（必填）
  name: string; // 菜品名称（必填，冗余字段）
  price: number; // 菜品单价（必填，冗余字段，单位：元）
  copies: number; // 份数（必填）
  setmealDishFlavors?: SetMealDishFlavor[]; // 套餐菜品口味列表（可选）
}

interface SetMealDishFlavor {
  flavorId: number; // 口味类型ID（必填，关联flavor表）
  flavorValue: string; // 默认口味值（必填，如"微辣"）
  flavorName?: string; // 口味类型名称（可选，冗余字段，如"辣度"）
  valueList?: string; // 口味值可选列表（可选，冗余字段，如"不辣,微辣,中辣,特辣"）
}
```

- **响应**: `ApiResponse<object>`

**说明**：

- `setmealDishes` 至少包含 1 个菜品
- 每个菜品的口味信息通过 `setmealDishFlavors` 数组传递，每种口味独立一行存入 `setmeal_dish_flavor` 表
- `flavorValue` 是管理员为该套餐中的菜品设置的口味默认值（如套餐A里的辣椒炒肉默认"微辣"）
- `flavorName` 和 `valueList` 为冗余字段，前端可传可不传，后端会从 `flavor` 表自动填充

### 3.2 修改套餐

- **Path**: `PUT /admin/setmeal`
- **Content-Type**: `application/json`
- **请求体**（对应 `SetMealDTO`）：

```typescript
interface SetMealDTO {
  id: number; // 套餐ID（必填）
  categoryId: number; // 分类ID（必填）
  name: string; // 套餐名称（必填）
  price: number; // 套餐价格（必填，单位：元，支持两位小数）
  status?: number; // 状态：0=停用，1=启用（可选）
  description?: string; // 描述信息（可选）
  image: string; // 图片URL（必填）
  setmealDishes: SetMealDish[]; // 套餐菜品列表（必填，至少1个菜品）
}
```

- **响应**: `ApiResponse<object>`

**说明**：修改套餐时，`setmealDishes` 采用全量覆盖逻辑。后端先删除该套餐在 `setmeal_dish` 和 `setmeal_dish_flavor` 表中的所有记录，再重新插入。

### 3.3 套餐分页查询

| `categoryId` | `number` | 否   | 分类ID               |
| `status`     | `number` | 否   | 状态：0=停用，1=启用 |

- **响应**: `ApiResponse<PageResult<SetMealVO>>`

```typescript

  description: string; // 描述信息
  image: string; // 图片URL

interface OrderVO {

  id: number; // 订单主键

  remark: string; // 备注信息
  userName: string; // 用户名
  phone: string; // 手机号
  address: string; // 地址
  consignee: string; // 收货人
  cancelReason: string; // 订单取消原因
  rejectionReason: string; // 订单拒绝原因
  cancelTime: string; // 订单取消时间

  deliveryStatus: number; // 配送状态：1-立即送出，0-选择具体时间
  deliveryTime: string; // 送达时间
  packAmount: number; // 打包数量

  tablewareStatus: number; // 餐具状态：1-按餐量打包，0-选择具体数量

  orderDetailList: OrderDetail[]; // 订单明细列表
}

interface OrderDetail {
  id: number; // 明细主键
  name: string; // 商品名称（下单时快照）
  orderId: number; // 订单ID
  dishId: number | null; // 菜品ID（单点菜品时有值，套餐时为null）
  setmealId: number | null; // 套餐ID（单点菜品时为null）
  flavorId: string; // 口味类型ID列表（逗号分隔，如 "1,2"）
  flavorName: string; // 口味类型名称列表（逗号分隔，如 "辣度,咸度"）
  flavorVal: string; // 指定口味值列表（逗号分隔，如 "微辣,少盐"）
  dishCopies: number; // 菜品数量（单点时为用户点的份数；套餐时为 setmeal_dish.copies × setmeal_copies）
  setmealCopies: number | null; // 套餐数量（仅套餐场景有值，单点时为null）
  amount: number; // 金额（单点时=菜品单价×dishCopies；套餐时=套餐单价×setmealCopies）
  image: string; // 图片URL（下单时快照）
  dishVO?: DishVO; // 菜品完整信息（仅当dishId不为空时填充）
  setmealVO?: SetMealVO; // 套餐完整信息（仅当setmealId不为空时填充）
}
```

**订单明细展示规则（重要）**：

数据库中的 `order_detail` 表存储逻辑：

- **单点菜品**：`setmealId = null`，`dishId != null` → 一条记录代表一个单点菜品
- **套餐内菜品**：`setmealId != null`，`dishId != null` → 一条记录代表套餐内的某个菜品

**字段说明**：

- `dishCopies`：菜品数量
  - 单点场景：用户点的该菜品的份数（如用户点了 2 份宫保鸡丁，`dishCopies = 2`）
  - 套餐场景：套餐内该菜品的份数 × 用户点的套餐份数（如套餐内宫保鸡丁 `copies = 1`，用户点了 2 份套餐，则 `dishCopies = 1 × 2 = 2`）
- `setmealCopies`：套餐数量（仅套餐场景有值）
  - 单点场景：`null`
  - 套餐场景：用户点的套餐份数（如用户点了 2 份"双人套餐A"，`setmealCopies = 2`）
- `amount`：金额
  - 单点场景：`菜品单价 × dishCopies`
  - 套餐场景：`套餐单价 × setmealCopies`（套餐内所有菜品的 `amount` 都相同，都是套餐总价）

后端返回时已做聚合处理：

- **单点菜品**：保持原样，`dishId` 有值，`dishVO` 填充完整菜品信息
- **套餐**：同一套餐的所有菜品已聚合为**一条** OrderDetail 记录
  - `dishId` 设为 `null`（因为代表的是套餐，不是单个菜品）
  - `name` 改为**套餐名称**（从 SetMealVO 中获取）
  - `setmealVO.setmealDishes` 替换为**用户实际点的菜品列表**（包含用户选择的口味），而非套餐模板数据
  - 前端应通过 `setmealVO.setmealDishes` 展示套餐内每个菜品的名称、份数、口味

**前端展示建议**：

```bash
遍历 orderDetailList：
 - 如果 dishId != null → 单点菜品，直接展示 name、dishCopies、amount，口味用 flavorName/flavorVal 配对展示
 - 如果 dishId == null && setmealId != null → 套餐
   - 展示套餐名称（name）
   - 展示套餐份数（setmealCopies）
   - 遍历 setmealVO.setmealDishes 展示套餐内每个菜品：
     - 菜品名称（setmealDish.name）
     - 份数（setmealDish.copies × setmealCopies）
     - 口味列表（setmealDish.setmealDishFlavors，每项展示 flavorName: flavorValue）
```

**口味字段说明**：

- 单点菜品：`flavorName` 和 `flavorVal` 一一对应，前端可按逗号拆分后配对展示
- 套餐内菜品：口味信息在 `setmealVO.setmealDishes[].setmealDishFlavors` 中，每个菜品独立存储
- 示例：`flavorName = "辣度,咸度"`，`flavorVal = "微辣,少盐"` → 展示为：

  ```bash
  辣度：微辣
  咸度：少盐
  ```

**dishVO / setmealVO 说明**：

- `dishVO` 包含菜品完整信息（名称、分类、价格、描述、图片、口味列表等），仅单点菜品时填充
- `setmealVO` 包含套餐完整信息（名称、分类、价格、描述、图片、套餐内菜品列表等），仅套餐时填充
  - `setmealVO.setmealDishes` 已被替换为用户实际点的菜品列表（含口味），不再是套餐模板数据
- 前端展示时，建议以 `OrderDetail` 的快照数据（`name`、`image`、`amount`）为准，因为订单是历史数据，不应随菜品价格变化而变化
